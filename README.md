# 아희 인터프리터 + 로컬 IDE

[아희(Aheui)](https://aheui.readthedocs.io/)는 한글 음절을 2차원 격자에 늘어놓는 난해한 프로그래밍 언어입니다.
이 저장소에는 속도에 초점을 맞춘 인터프리터(.NET 10, C#)와 브라우저용 디버깅 IDE가 들어 있습니다.

## 빠른 시작

```bash
dotnet build src/Aheui -c Release
```

```bash
src/Aheui/bin/Release/net10.0/aheui.exe samples/hello.aheui
```

```bash
src/Aheui/bin/Release/net10.0/aheui.exe ide
```

마지막 명령은 `http://localhost:8517/`에 IDE를 띄우고 브라우저를 엽니다.
`ide/index.html`을 그냥 파일로 열어도 됩니다. 이때는 네이티브 실행 버튼만 빠집니다.

### 명령줄 옵션

| 옵션 | 뜻 |
| --- | --- |
| `aheui <파일>` | 실행 (`-`면 표준 입력에서 코드를 읽음) |
| `aheui -c "<코드>"` | 코드 문자열 실행 |
| `aheui ide [--port N] [--no-browser]` | 로컬 IDE 서버 |
| `--stats` | 노드 수, 컴파일/실행 시간, JIT 정보를 표준 오류로 출력 |
| `--profile` | 명령 종류별/노드별 실행 횟수 (느려짐) |
| `--dump` | 컴파일된 명령 그래프 출력 |
| `--no-jit` / `--no-opt` | JIT 끄기 / 핍홀 최적화 끄기 |

환경 변수 `AHEUI_JIT_THRESHOLD`로 JIT 전환 시점(실행한 명령 수, 기본 3천만)을 바꿀 수 있습니다.

## 인터프리터 구조와 최적화

```
코드 → CodeSpace(격자) → Compiler(명령 그래프) → Optimizer(핍홀) → 해석기 ──(3천만 명령 후)──▶ JIT(IL → 기계어)
                                                                  └─ 64비트 넘침 시 ─▶ BigInteger 해석기
```

1. **명령 그래프로 컴파일** (`Compiler.cs`)
   상태 = (칸, 홀소리 적용 후 방향, 현재 저장공간)마다 노드를 하나 만들고, 시작점에서 닿는 것만 만듭니다.
   - 빈칸, 한글이 아닌 글자, ㅇ/ㄱ/ㄲ/ㅉ/ㅋ, **ㅅ(저장공간 선택)**은 컴파일할 때 따라가서 간선으로 접습니다.
     실행 중에는 커서 이동이나 방향 계산을 하지 않습니다.
   - 저장공간이 정적으로 정해지므로 스택용·큐용 명령을 따로 고릅니다.
   - 명령 없이 도는 순환은 `Loop` 노드로 감지합니다.
   - 각 노드에는 정상 진행 간선과, 저장공간이 부족할 때 반대로 가는 간선이 따로 있습니다.
2. **핍홀 최적화** (`Optimizer.cs`, 스택에만 적용)
   - `ㅂ k; ㄷ` → `AddC k`. 스택이 비었을 때 쓸 보정 노드를 같이 만듭니다.
   - 상수 접기: `ㅂ a; ㅂ b; ㄸ` → `ㅂ (a*b)`. 상수 덧셈과 곱셈이 이어지면 하나로 합칩니다.
   - `ㅈ; ㅊ` → `CmpBr` (비교와 분기를 합침). `ㅂ k; ㅊ` → 분기 방향을 컴파일할 때 정합니다.
   - `ㅂ; ㅁ` → 제거. `ㅂ k; ㅁㅇ` → 상수 출력.
   - Nop 간선을 건너뛰게 다시 잇고, 도달 가능한 노드만 BFS 순서로 다시 번호를 매깁니다.
3. **해석기** (`Vm.cs`)
   - 24바이트 `Instr` 배열을 `switch`로 실행합니다.
   - 저장공간은 구조체 배열로 두고 `ref`로 접근합니다. 범위 검사는 `Unsafe`로 없앴습니다.
   - 값 표현(`long`/`BigInteger`)마다 구조체 제네릭으로 특화한 코드를 JIT이 따로 만듭니다.
4. **JIT** (`Jit.cs`)
   - 3천만 명령 넘게 도는 프로그램만 명령 그래프를 `DynamicMethod` IL로 바꿉니다. 노드는 레이블이 되고 간선은 직접 분기가 됩니다.
   - 자주 쓰는 스택 명령은 IL을 직접 만듭니다. 곱셈은 32비트 안의 값이면 넘침 검사를 생략합니다.
   - RyuJIT는 너무 큰 메서드를 최적화하지 않으므로 256노드 단위로 나누고, 덩어리 사이 이동은 트램펄린 루프가 맡습니다. 실제로 실행되는 덩어리만 컴파일합니다.
5. **임의 정밀도**: 빠른 경로는 `long`이고 모든 연산에서 넘침을 검사합니다.
   넘치면 그 명령에서 멈추고 저장공간을 `BigInteger`로 옮긴 뒤 같은 명령부터 다시 실행합니다.

측정값(같은 기계, 시간대마다 편차가 큼):

| 프로그램 | 최적화 없음 | 그래프+핍홀 | +JIT |
| --- | --- | --- | --- |
| `snippets/logo` (명령 8.9억 개) | ~10.5 s | ~6.3 s | ~4.5 s |
| `bench/loop.aheui` (1.5억 개) | – | ~0.7 s | ~0.2 s |

## 구현에서 정한 동작 (표준에서 정의하지 않은 부분)

- 코드 공간 밖으로 나가면 반대편 끝으로 갑니다. 가로는 **그 줄의 길이**, 세로는 전체 줄 수가 기준입니다.
  두 칸 이동이 끝을 넘으면 반대편 끝 칸으로 갑니다. 줄보다 짧은 위치는 빈칸으로 취급합니다. 파일 끝의 빈 줄은 무시합니다.
- 나눗셈과 나머지는 0 쪽으로 버림합니다(C와 같음). 0으로 나누면 오류를 내고 종료 코드 1로 끝납니다.
- 숫자 입력: 공백을 건너뛰고 `[+-]?[0-9]+`를 읽습니다. EOF이거나 숫자가 아니면 -1입니다. 문자 입력도 EOF면 -1입니다.
- 출력할 수 없는 코드값(음수, 서로게이트, 0x10FFFF 초과)은 U+FFFD로 출력합니다.
- ㅎ 통로(받침 ㅎ 저장공간)는 스택으로 취급합니다.
- 명령 없이 무한히 도는 경로에 들어가면 경고를 출력하고 CPU를 쓰지 않은 채 대기합니다.

## IDE (`ide/`)

빌드 도구 없이 동작하는 HTML/JS이며, 참고: [aheui/avis](https://github.com/aheui/avis).

- 왼쪽은 코드 편집기이고, 가운데는 코드 공간입니다. 코드 공간은 명령 종류별로 색을 칠하고, 현재 커서와 지나온 길을 표시합니다. 칸을 누르면 중단점이 생깁니다.
- 실행, 일시정지, 한 단계 실행, 초기화, 속도 조절을 할 수 있습니다. 단축키는 F5, F6, F10, Shift+F5입니다.
- 저장공간 28개 중 값이 있는 것과 현재 선택된 것을 보여줍니다. 입출력 창과 파일 열기·저장, 예제가 있습니다.
- `aheui ide`로 열면 **⚡ 네이티브 실행**(Ctrl+Enter)으로 C# 인터프리터를 별도 프로세스로 돌립니다. 시간 제한은 30초입니다.
- IDE의 단계 실행기(`ide/aheui.js`)는 BigInt를 쓰며 네이티브와 같은 규칙을 따릅니다.

## 테스트

[aheui/snippets](https://github.com/aheui/snippets) 표준 테스트 모음을 사용합니다.

```bash
git clone --depth 1 https://github.com/aheui/snippets.git tests/snippets
```

```bash
uv run --no-project python tests/run_snippets.py tests/snippets
```

```bash
uv run --no-project python tests/run_snippets.py tests/snippets --flags=--no-jit
```

```bash
node tests/run_js_snippets.js tests/snippets
```

`AHEUI_JIT_THRESHOLD=0`을 주면 처음부터 JIT으로 실행하므로 JIT 경로도 같은 테스트로 검사할 수 있습니다.
현재 결과는 네이티브(해석기, JIT, 최적화 없음) 모두 60/60입니다.
IDE 실행기는 59/59이고, logo는 너무 길어서 건너뜁니다.
