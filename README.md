# 아희 인터프리터 + 로컬 IDE

[아희(Aheui)](https://aheui.readthedocs.io/)는 한글 음절을 2차원 격자에 늘어놓는 난해한 프로그래밍 언어입니다.
이 저장소에는 속도에 초점을 맞춘 인터프리터(.NET 10, C#)와 아희 전용 데스크톱 IDE가 들어 있습니다.

## 빠른 시작

```bash
dotnet build aheui.slnx -c Release
```

```bash
src/Aheui/bin/Release/net10.0/aheui.exe samples/hello.aheui
```

```bash
src/Aheui.Ide/bin/Release/net10.0-windows/aheui-ide.exe
```

`aheui-ide.exe`는 별도 창(WebView2)으로 IDE를 띄웁니다. 파일 경로를 인자로 주면 그 파일을 열고 시작합니다.
UI를 고치는 중이라면 환경 변수 `AHEUI_IDE_DIR`에 저장소의 `ide` 폴더를 지정하세요. 그러면 다시 빌드하지 않고 창에서 새로고침만 하면 됩니다.

### 프로젝트 구성

| 경로 | 내용 |
| --- | --- |
| `src/Aheui.Core` | 컴파일러, 최적화기, 해석기, JIT, 입출력, 명령줄 처리 (라이브러리) |
| `src/Aheui` | `aheui` 명령줄 인터프리터 |
| `src/Aheui.Ide` | `aheui-ide` 데스크톱 창 (WinForms + WebView2). 파일 대화상자와 네이티브 실행을 맡음 |
| `ide/` | IDE 화면 (HTML/JS, 빌드 도구 없음) |

### 명령줄 옵션

| 옵션 | 뜻 |
| --- | --- |
| `aheui <파일>` | 실행 (`-`면 표준 입력에서 코드를 읽음) |
| `aheui -c "<코드>"` | 코드 문자열 실행 |
| `--stats` | 노드 수, 컴파일/실행 시간, JIT 정보를 표준 오류로 출력 |
| `--profile` | 명령 종류별/노드별 실행 횟수 (느려짐) |
| `--dump` | 컴파일된 명령 그래프 출력 |
| `--no-jit` / `--no-opt` | JIT 끄기 / 핍홀 최적화 끄기 |

환경 변수 `AHEUI_JIT_THRESHOLD`로 JIT 전환 시점(실행한 명령 수, 기본 3천만)을 바꿀 수 있습니다.

## 인터프리터 구조와 최적화

```
코드 → CodeSpace(격자) → Compiler(명령 그래프) → Optimizer(핍홀) → 해석기 ──(3천만 명령 후)──▶ JIT(IL → 기계어)
                                                                  └─ 64비트 넘침 시 ─▶ BigInteger 해석기
```

1. **명령 그래프로 컴파일** (`Compiler.cs`)
   상태 = (칸, 홀소리 적용 후 방향, 현재 저장공간)마다 노드를 하나 만들고, 시작점에서 닿는 것만 만듭니다.
   - 빈칸, 한글이 아닌 글자, ㅇ/ㄱ/ㄲ/ㅉ/ㅋ, **ㅅ(저장공간 선택)**은 컴파일할 때 따라가서 간선으로 접습니다.
     실행 중에는 커서 이동이나 방향 계산을 하지 않습니다.
   - 저장공간이 정적으로 정해지므로 스택용·큐용 명령을 따로 고릅니다.
   - 명령 없이 도는 순환은 `Loop` 노드로 감지합니다.
   - 각 노드에는 정상 진행 간선과, 저장공간이 부족할 때 반대로 가는 간선이 따로 있습니다.
2. **핍홀 최적화** (`Optimizer.cs`, 스택에만 적용)
   - `ㅂ k; ㄷ` → `AddC k`. 스택이 비었을 때 쓸 보정 노드를 같이 만듭니다.
   - 상수 접기: `ㅂ a; ㅂ b; ㄸ` → `ㅂ (a*b)`. 상수 덧셈과 곱셈이 이어지면 하나로 합칩니다.
   - `ㅈ; ㅊ` → `CmpBr` (비교와 분기를 합침). `ㅂ k; ㅊ` → 분기 방향을 컴파일할 때 정합니다.
   - `ㅂ; ㅁ` → 제거. `ㅂ k; ㅁㅇ` → 상수 출력.
   - Nop 간선을 건너뛰게 다시 잇고, 도달 가능한 노드만 BFS 순서로 다시 번호를 매깁니다.
3. **해석기** (`Vm.cs`)
   - 24바이트 `Instr` 배열을 `switch`로 실행합니다.
   - 저장공간은 구조체 배열로 두고 `ref`로 접근합니다. 범위 검사는 `Unsafe`로 없앴습니다.
   - 값 표현(`long`/`BigInteger`)마다 구조체 제네릭으로 특화한 코드를 JIT이 따로 만듭니다.
4. **JIT** (`Jit.cs`)
   - 3천만 명령 넘게 도는 프로그램만 명령 그래프를 `DynamicMethod` IL로 바꿉니다. 노드는 레이블이 되고 간선은 직접 분기가 됩니다.
   - 자주 쓰는 스택 명령은 IL을 직접 만듭니다. 곱셈은 32비트 안의 값이면 넘침 검사를 생략합니다.
   - RyuJIT는 너무 큰 메서드를 최적화하지 않으므로 256노드 단위로 나누고, 덩어리 사이 이동은 트램펄린 루프가 맡습니다. 실제로 실행되는 덩어리만 컴파일합니다.
5. **임의 정밀도**: 빠른 경로는 `long`이고 모든 연산에서 넘침을 검사합니다.
   넘치면 그 명령에서 멈추고 저장공간을 `BigInteger`로 옮긴 뒤 같은 명령부터 다시 실행합니다.

측정값(같은 기계, 시간대마다 편차가 큼):

| 프로그램 | 최적화 없음 | 그래프+핍홀 | +JIT |
| --- | --- | --- | --- |
| `snippets/logo` (명령 8.9억 개) | ~10.5 s | ~6.3 s | ~4.5 s |
| `bench/loop.aheui` (1.5억 개) | – | ~0.7 s | ~0.2 s |

## 구현에서 정한 동작 (표준에서 정의하지 않은 부분)

- 코드 공간 밖으로 나가면 반대편 끝으로 갑니다. 가로는 **그 줄의 길이**, 세로는 전체 줄 수가 기준입니다.
  두 칸 이동이 끝을 넘으면 반대편 끝 칸으로 갑니다. 줄보다 짧은 위치는 빈칸으로 취급합니다. 파일 끝의 빈 줄은 무시합니다.
- 나눗셈과 나머지는 0 쪽으로 버림합니다(C와 같음). 0으로 나누면 오류를 내고 종료 코드 1로 끝납니다.
- 숫자 입력: 공백을 건너뛰고 `[+-]?[0-9]+`를 읽습니다. EOF이거나 숫자가 아니면 -1입니다. 문자 입력도 EOF면 -1입니다.
- 출력할 수 없는 코드값(음수, 서로게이트, 0x10FFFF 초과)은 U+FFFD로 출력합니다.
- ㅎ 통로(받침 ㅎ 저장공간)는 스택으로 취급합니다.
- 명령 없이 무한히 도는 경로에 들어가면 경고를 출력하고 CPU를 쓰지 않은 채 대기합니다.

## IDE

[aheui/avis](https://github.com/aheui/avis)를 참고했습니다. 코드 공간은 캔버스에 직접 그리고, 키 입력은 운영체제 IME를 거치지 않습니다. 물리 키를 읽어 자체 두벌식 입력기(`ide/js/ime.js`)로 조합합니다.

### 키보드 (코드 공간)

| 키 | 동작 |
| --- | --- |
| 한글 자판 | 두벌식으로 조합해 현재 칸에 입력합니다. 한 글자가 완성되어 다음 글자로 넘어가면 커서가 오른쪽으로 갑니다. 홀소리만 치면 초성 ㅇ이 붙고, 한글이 아닌 글자는 입력되지 않습니다. |
| Space | 조합을 끝내고 오른쪽으로 한 칸 띄웁니다. |
| 화살표 | 조합을 끝내고 그 방향 칸으로 이동합니다. Enter로는 줄을 바꾸지 않습니다. |
| `[` / `]` | 줄 처음 / 줄 끝(마지막 글자 다음)으로 이동합니다. |
| `,` / `.` | 한 단계 뒤로 / 한 단계 실행 |
| Backspace / Delete | 조합 한 단계 지우기, 왼쪽 칸 지우기 / 현재 칸 지우기 (선택이 있으면 선택 영역 삭제) |
| Ctrl+Z / Ctrl+Y | 되돌리기 / 다시 하기 |
| Ctrl+C / Ctrl+X / Ctrl+V | 선택 영역 복사 / 잘라내기 / 가장 최근 클립을 커서 위치에 붙여넣기 |
| Ctrl+휠 | 확대 / 축소 |
| F5, Shift+F5, F6, F10 | 실행·계속, 초기화, 일시정지, 한 단계 |
| Ctrl+Enter | 네이티브 인터프리터로 전속력 실행 (30초 제한) |
| Alt+1~6 | 마우스 도구 바꾸기 |

### 마우스 도구

- **커서**: 클릭한 칸으로 입력 위치를 옮깁니다.
- **펜**: 끌어서 칸 배경을 칠합니다(색 6가지). 오른쪽 버튼으로 끌면 지웁니다.
- **중단점**: 클릭으로 찍고 지웁니다. 실행이 그 칸에 오면 멈춥니다.
- **선택 도구**: 사각형, 올가미(테두리를 그린 안쪽), 붓(지나간 칸)이 있습니다. Shift를 누르면 선택에 더하고, Alt를 누르면 선택에서 뺍니다.

### 실행 경로 화살표

실행한 이동을 화살표로 그립니다. 화살표는 글자 사이 빈 곳에만 그립니다. 배경색 테두리를 둘러서 형광펜 위에서도 잘 보이고, 오가는 경로는 옆으로 비켜 그려서 겹치지 않습니다. 오래된 경로는 흐려집니다.

### 클립보드

선택한 글자를 프로그램 내부 클립보드에 담습니다(형광펜 색 포함). 왼쪽 목록에서 끌어 원하는 자리에 놓으면 모양 그대로 붙습니다. 놓기 전에 미리보기가 나오고, 다른 글자와 겹치는 칸은 빨갛게 표시됩니다. 겹치는 칸이 있으면 덮어쓰기, 빈 칸에만 붙이기, 취소 중에서 고르는 확인 창이 뜹니다.

### 보조 코드 공간

**＋ 코드 공간**을 누르면 메인 위에 떠 있는 창이 하나 생깁니다. 보조 창마다 실행 상태, 입력, 버전 기록이 따로 있습니다. 제목 막대를 끌어 옮기고, 모서리로 크기를 바꾸고, 최소화(아래 목록에 남음)하거나 닫을 수 있습니다. 오른쪽 패널은 마지막으로 누른 코드 공간의 상태를 보여줍니다.

### 한 줄 팔레트

1. 왼쪽 팔레트 줄에 코드를 한 줄로 씁니다. 예: `방방다망희`
2. ⠿ 손잡이를 끌어 코드 공간 위를 지나가면, 지나가는 길을 따라 한 글자씩 놓입니다.
   - 각 글자의 홀소리는 다음 글자가 있는 방향(ㅏㅓㅗㅜ)으로 바뀝니다. 마지막 글자는 원래 홀소리를 유지합니다.
   - Shift를 누른 채 지나간 곳은 두 칸 이동(ㅑㅕㅛㅠ)으로 놓습니다. 건너뛰는 가운데 칸은 차 있어도 됩니다.
   - 기존 글자는 덮어쓰지 않습니다. 글자가 있는 칸에서는 더 나아가지 않습니다.
   - 놓았던 칸으로 되돌아가면 그 뒤에 놓인 글자들이 거둬집니다.
3. 놓으면 배치한 칸들이 강조 표시됩니다. **Enter로 적용**하고, Esc로 취소합니다.

### 버전 (간단한 git)

- 모든 편집은 되돌리기 기록에 남습니다(연속 타이핑은 하나로 묶임). **버전** 탭에 최근 기록이 보입니다.
- **커밋**하면 지금 상태(글자, 형광펜, 중단점)를 메시지와 함께 저장합니다.
- 커밋마다 **비교**(지금과 다른 칸을 주황 테두리로 표시)와 **복원**을 할 수 있습니다. 복원하기 전에 지금 상태가 마지막 커밋과 다르면 자동으로 먼저 커밋하고, 복원도 Ctrl+Z로 되돌릴 수 있습니다.

### 저장

- 작업 공간 전체(모든 코드 공간, 창 위치, 팔레트, 클립보드, 커밋)는 자동으로 저장되고, 다음에 열면 그대로 복원됩니다.
- **열기 / 저장**은 활성 코드 공간을 `.aheui` 파일로 다룹니다.
- **프로젝트 열기 / 저장**은 작업 공간 전체를 `.aheuiproj`(JSON) 파일로 다룹니다.
- 브라우저에서 `ide/index.html`을 직접 열어도 동작합니다. 이때 네이티브 실행은 빠지고, 저장은 내려받기로 대신합니다.

## 테스트

[aheui/snippets](https://github.com/aheui/snippets) 표준 테스트 모음을 사용합니다.

```bash
git clone --depth 1 https://github.com/aheui/snippets.git tests/snippets
```

```bash
uv run --no-project python tests/run_snippets.py tests/snippets
```

```bash
uv run --no-project python tests/run_snippets.py tests/snippets --flags=--no-jit
```

```bash
node tests/run_js_snippets.js tests/snippets
```

```bash
node tests/ime.test.mjs
```

`AHEUI_JIT_THRESHOLD=0`을 주면 처음부터 JIT으로 실행하므로 JIT 경로도 같은 테스트로 검사할 수 있습니다.
현재 결과는 네이티브(해석기, JIT, 최적화 없음) 모두 60/60입니다.
IDE 실행기는 59/59(되감기 검사 포함)이고, logo는 너무 길어서 건너뜁니다. 입력기 테스트는 22/22입니다.
