# 아희 작업 방법

아희는 2차원 언어라서 **칸 위치를 머리로 세거나 실행 흐름을 머리로 따라가면 거의 반드시 틀린다.**
코드를 읽거나 고치기 전에 아래 도구로 텍스트 출력을 얻고, 그 출력만 근거로 추론한다.

## 도구 (이 저장소의 인터프리터)

먼저 한 번 빌드한다: `dotnet build src/Aheui -c Release` → `src/Aheui/bin/Release/net10.0/aheui.exe` (아래에서 `aheui`).

| 하고 싶은 것 | 명령 |
| --- | --- |
| 칸마다 좌표·분해·명령 보기 | `aheui explain 파일 [--rows 3:7] [--grid-only \| --cells-only]` |
| 실제 실행 흐름을 선형 코드로 보기 | `aheui asm 파일` (도달 가능한 명령만, 라벨/분기 포함, 각 줄에 원래 좌표) |
| 한 단계씩 실행 기록 | `aheui trace 파일 --input "1 2\n" [--steps N] [--from N] [--at x,y] [--cmds-only] [--until-output]` |
| 구현 차이·채점기 함정 경고 | `aheui lint 파일` |
| 실제 실행 (빠름) | `aheui 파일 < 입력` / `aheui -c "코드"` |
| 백준 채점기와 같은 입력 규칙으로 실행 | `aheui --rpaheui-input 파일 < 입력` / `aheui trace 파일 --rpaheui-input --input "..."` |

- 좌표 (x,y) = (줄 안의 칸 번호, 줄 번호), 둘 다 0부터.
- `trace` 저장공간 표기: `*` = 현재 선택, 스택 `ㄷ[아래 … 위>`, 큐 `ㅇ<앞 … 뒤]`. `--steps 0`은 무제한.
- `--input`의 `\n`은 개행으로 바뀐다. 입력을 안 주면 표준 입력을 읽는다.
- 큰 프로그램은 `trace --cmds-only --at x,y`로 의심 칸만 보거나 `--from`으로 뒷부분만 본다.

## 작업 순서

1. **읽기**: `explain`으로 격자와 칸 표를 얻고 `asm`으로 흐름(루프, 분기, 출구)을 파악한다.
2. **동작 확인**: 실제 입력으로 `aheui 파일`을 실행하고, 기대와 다르면 `trace`로 처음 어긋나는 단계를 찾는다.
3. **고치기**: 수정할 칸을 `(x,y)`로 특정해 그 칸만 바꾼다. 줄 길이가 바뀌면 감싸기 위치가 바뀌므로 다시 `explain`/`trace`로 확인한다.
4. **제출 전**: `lint`를 돌려 경고를 확인한다.

## 문법 요약

음절 하나 = 명령 하나. **초성 = 명령, 중성(홀소리) = 다음 이동 방향, 받침 = 인자.**
커서는 (0,0)에서 아래 방향으로 시작하고, 저장공간은 받침 없음(`_`, 스택)이 선택되어 있다.

초성 (a b = 먼저 넣은 값 a, 위의 값 b; 꺼낸 두 값 대신 결과 하나를 넣음):

| 초성 | 명령 | 동작 |
| --- | --- | --- |
| ㅇ ㄱ ㄲ ㅋ ㅉ | 없음 | 아무것도 안 함 (방향만 적용) |
| ㅎ | 끝 | 종료. 현재 저장공간에서 꺼낸 값이 종료 코드 (비었으면 0) |
| ㄷ ㄸ ㅌ ㄴ ㄹ | 셈 | a+b, a*b, a-b, a/b, a%b (나눗셈은 0 쪽으로 버림) |
| ㅈ | 비교 | a>=b 면 1, 아니면 0 |
| ㅁ | 뽑기 | 받침 ㅇ: 숫자 출력, ㅎ: 문자 출력, 그 외: 버림 |
| ㅂ | 넣기 | 받침 ㅇ: 숫자 입력, ㅎ: 문자 입력, 그 외: 받침 획수를 넣음 (받침 없으면 0) |
| ㅃ | 중복 | 맨 위(큐는 맨 앞) 값 복제 |
| ㅍ | 바꿔치기 | 위의 두 값을 바꿈 |
| ㅅ | 선택 | 받침에 해당하는 저장공간을 선택 |
| ㅆ | 이동 | 꺼내서 받침 저장공간에 넣음 |
| ㅊ | 조건 | 꺼내서 0이면 반대 방향, 아니면 그대로 |

받침 획수(ㅂ): ㄱ2 ㄴ2 ㄷ3 ㅁ4 ㅂ4 ㅅ2 ㅈ3 ㅊ4 ㅋ3 ㅌ4 ㅍ4 ㄲ4 ㅆ4 ㄹ5 ㄳ4 ㄵ5 ㄶ5 ㄺ7 ㄻ9 ㄼ9 ㄽ7 ㄾ9 ㄿ9 ㅀ8 ㅄ6.

홀소리: ㅏ→ ㅓ← ㅗ↑ ㅜ↓ / ㅑ ㅕ ㅛ ㅠ 같은 방향 두 칸 / ㅡ 세로로 가던 중이면 반대 / ㅣ 가로로 가던 중이면 반대 / ㅢ 무조건 반대 / 나머지(ㅐ ㅔ ㅚ …) 방향 유지.

저장공간: 받침 27종(없음 포함). ㅇ = 큐, ㅎ = 통로(이 구현은 스택), 나머지는 스택.

- **값이 모자라면** 명령을 실행하지 않고 반대 방향으로 간다. 루프 출구로 자주 쓴다.
- 코드 밖으로 나가면 반대쪽 끝으로 감싼다. 짧은 줄의 밖은 빈칸이다.
- 입력이 끝나면 숫자/문자 입력은 이 구현에서 -1이다.

## 자주 하는 실수와 함정

- 방향은 **그 칸의 홀소리를 적용한 뒤** 이동한다. 값이 모자라거나 ㅊ에서 0이면, 그 칸의 홀소리를 적용한 방향의 반대로 간다.
- ㅌ/ㄴ/ㄹ/ㅈ의 순서: 먼저 넣은 값이 왼쪽 피연산자다 (`ㅂ5 ㅂ2 ㅌ` → 5-2=3).
- `ㅁ`(받침 없음)은 출력이 아니라 버리기다. 숫자 출력은 `망`, 문자 출력은 `맣`.
- 두 칸 홀소리(ㅑㅕㅛㅠ)로 가장자리를 넘으면 구현마다 착지 칸이 다르다. `lint`가 알려 준다.
- **백준**(채점기 rpaheui 1.2.2-24, `-O2`):
  - 종료 코드가 0이 아니면 런타임 에러다. 빈 저장공간을 선택한 뒤 `ㅎ`으로 끝낸다.
  - 숫자 입력은 숫자 앞 공백을 건너뛰지 않고, 숫자가 없으면 오류다. **숫자 바로 뒤의 공백/탭/개행 하나를 먹는다** (`3 ABC`에서 숫자 뒤 공백을 문자 입력으로 따로 버리면 S의 첫 글자가 사라진다). ``은 먹지 않으므로 CRLF 입력이면 런타임 에러.
  - 백준 제출 전 확인은 항상 `--rpaheui-input`으로 한다. 기본 모드는 숫자 앞 공백을 건너뛰고 뒤 공백을 남겨서 로컬에서만 맞을 수 있다.
  - rpaheui는 입력을 1바이트마다 시스템 호출로 읽어서 입력이 수백 KB 이상이면 코드와 상관없이 시간 초과가 날 수 있다.
  - `-O2` 최적화 버그로, 다른 루프가 저장공간을 채운 뒤에야 비는 "값 부족 출구"가 지워질 수 있다. 로컬에서는 맞는데 백준에서만 런타임 에러라면, 개수 세는 값을 따로 두고 ㅊ로 빠져나가게 바꾼다.
